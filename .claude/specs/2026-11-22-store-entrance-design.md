# ストアの入口を直すリリース（2.0.1）設計

## 目的
週間ユーザー約300人（日本80%）。半年の実インストールは1日2〜3件で、ストア内の表示は30日で212回、ストアページの閲覧は127回しかない。離脱（半年で128件、入れた人の約3割）より「見つけてもらえない」ことが詰まりになっている。どこから来た人も最後はストアページを通るので、外への発信（Zenn / Qiita / note / X / Reddit / AlternativeTo）の前に、ストアの入口を直し、流入元を測れるようにする。対象は日本と英語圏の両方。

## やること / やらないこと
- やる: ストア検索に載る名前、流入元の計測（UTM）、やめた理由の把握、レビューを貯めやすくする、ストア説明文の書き直し
- やらない: 拡張内での利用状況の計測（「データは外部サーバーに送信されません」の約束を守る）、機能追加、Product Hunt（レビューが貯まってから）
- 失敗とみなすもの: 検索語の詰め込みでストアの審査に落ちる、プライバシーの約束を崩す

## 進め方の比較（決定済み: A）
- **A. 入口を直してから発信（採用）**: 発信で来た人を取りこぼしにくく、効果をUTMで測れる。発信がリリースと審査の分だけ遅れる
- B. すぐ発信: 最速だが、名前が弱くレビューも少ないストアページに人を送ることになり、何が効いたかも測れない
- C. 検索・AI向けの土台作り: 効果が積み上がるが数か月かかる。Aの後に続ける

## 変更内容
1. **拡張名を言語別に**: `manifest.*.json` の `name` を `__MSG_appName__` にし、`short_name` は `SideTimeTable` のまま。
   - ja: `SideTimeTable - サイドパネルでGoogleカレンダー`
   - en / en_US: `SideTimeTable - Google Calendar in Side Panel`
   - （名前の案は Claude の判断。75文字以内、詰め込みにならない一言の説明に留める）
2. **ストアへのリンクにUTM**: `utm_source` で流入元を分ける。
   - ランディングページ（ja: `landing_ja`、en: `landing_en`。旧URL `chrome.google.com/webstore/...` は新URL `chromewebstore.google.com/...` にそろえる）
   - README（`github`）、告知ワークフローの `STORE_URL`（`utm_source` は投稿先ごとに付ける）
   - 拡張内のレビュー依頼のリンク（`review_prompt`）
3. **アンインストール時のアンケート**: `background.js` の `onInstalled` で `chrome.runtime.setUninstallURL()` を設定する。行き先は日英併記の Google フォーム（作成は利用者。質問の案は Claude が用意）。拡張のバージョンと表示言語だけを事前入力のパラメータで渡し、それ以外は送らない。プライバシーポリシー（日英）に一文足す。
4. **レビュー依頼の条件を緩める**: 合計10日以上 → 5日以上（2日連続・「あとで」から7日は据え置き）。数字は Claude の判断。
   - **Googleカレンダー連携の条件を外す**: 今はアカウントなしの利用者には一度も出ない（Claude の提案、利用者了承）。
6. **定着した利用者への再依頼（利用者決定: 案 a）**: 「レビューを書く」を押した人に、1回だけもう一度聞く。
   - 条件: 押してから60日以上たち、その間に20日以上パネルを開いている（数字は Claude の判断）。2.0.1 より前に押した人は押した日が記録されていないので、日数の条件は満たしたものとし、2.0.1 で開いた日数だけを数える。
   - 文面は再依頼用（「使い続けてくださってありがとうございます。最近のアップデートを踏まえて、レビューを書いたり更新したりしませんか？」— 文面は Claude の判断。ストアのレビューは後から書き直せる）。
   - 「レビューを書く」→ 以後は聞かない。「あとで」→ 7日後に再依頼の文面でもう一度。「今後表示しない」→ 以後は聞かない。
   - 「今後表示しない」を押した人には再依頼しない（案 b は不採用: ボタンの約束を破り、低評価を招く恐れがある）。
5. **ストア詳細説明文**: `store/descriptions.md` を、日英とも検索されそうな語（Googleカレンダー、サイドパネル、タイムライン、リマインダー、Meet など）を自然に含む形に書き直す。ダッシュボードへの貼り付けは利用者。

## 残っていること（利用者の作業）
- Google フォームを作って URL を渡す（3 で使う）
- 2.0.1 をストアに出し、説明文を貼り替える
- 1〜2週間後、ダッシュボードでストア内表示・ページ閲覧・`utm_source` 別の閲覧を確認する

## 実装者に任せること
- ランディングページの英語版は `npm run build:landing` で作り直す
- テスト（`setUninstallURL` の呼び出し、レビュー条件の境界、ロケールの `appName`）を足し、`npm test` / `npm run lint` / `npm run build` を通す
